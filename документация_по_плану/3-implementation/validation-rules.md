# Validation Rules — Правила валідації

> Модель призначена для навчального прототипу і не є затвердженою схемою сховища даних промислового застосування.

## Контекст матчу

| Поле | Тип | Правило | Приклад валідного | Приклад невалідного | Повідомлення про помилку |
|---|---|---|---|---|---|
| `hero` | рядок | обов'язковий, ідентифікатор героя з довідника | `antimage` | `""`, `unknown_hero` | «Оберіть існуючого героя» |
| `role` | перелік | допустимі ролі: carry, mid, offlane, support, hard_support | `carry` | `tank` | «Роль не входить до переліку» |
| `enemyHeroes` | масив рядків | ідентифікатори існуючих героїв, без дублів, ≤ 5 | `["axe","cm"]` | `["axe","axe"]`, 6 елементів | «Список супротивників містить дубль» / «Максимум 5 супротивників» |
| `gameStage` | перелік | early, mid, late | `mid` | `final` | «Стадія матчу має бути early/mid/late» |
| `patch` | рядок | формат `X.YZ` або `unverified` | `7.37d`, `unverified` | `abc` | «Формат версії патчу: X.YZ або unverified» |

## Правила валідації (порядок виконання)

1. Перевірити наявність обов'язкових полів (`hero`).
2. Нормалізувати ідентифікатори (trim, lowercase) та відхилити невідомі значення.
3. Перевірити, чи роль допустима для обраного сценарію.
4. Обмежити розмір списку супротивників (≤ 5) та видалити повторення.
5. Перевірити формат версії патча.
6. Не запускати обчислення, якщо актуальна версія даних невідома та політика проєкту забороняє такий запит.
7. Не зберігати зайвих особистих даних користувача.

## Приклади

### Валідний запит

```json
{
  "hero": "antimage",
  "role": "carry",
  "enemyHeroes": ["axe", "legion_commander", "crystal_maiden"],
  "gameStage": "early",
  "patch": "7.37d"
}
```

### Невалідний запит — порожній hero

```json
{
  "hero": "",
  "role": "carry",
  "enemyHeroes": [],
  "gameStage": "early",
  "patch": "7.37d"
}
```
**Результат:** `400 VALIDATION_ERROR` — «Поле 'hero' є обов'язковим»

### Невалідний запит — дубль супротивників

```json
{
  "hero": "antimage",
  "role": "carry",
  "enemyHeroes": ["axe", "axe"],
  "gameStage": "early",
  "patch": "7.37d"
}
```
**Результат:** `400 VALIDATION_ERROR` — «Список супротивників містить дубль»

### Невалідний запит — невідома роль

```json
{
  "hero": "antimage",
  "role": "tank",
  "enemyHeroes": [],
  "gameStage": "early",
  "patch": "7.37d"
}
```
**Результат:** `400 VALIDATION_ERROR` — «Роль не входить до переліку»

## Обробка неповних даних

Якщо для поєднання героя, ролі та патча немає перевірених правил, сервіс має повернути зрозуміле попередження або помилку, а не вигадувати точну рекомендацію. У інтерфейсі показується, яких даних не вистачає.

## Зв'язок з тестами

Кожне правило має щонайменше один позитивний і один негативний тест-кейс (див. `4-quality/test-cases.md` TC-07 — TC-11).
