## Основні сценарії

### UC-1: Ввести параметри матчу

**Передумови:** Гравець на головному екрані.

**Основний потік:**
1. Гравець обирає героя зі списку.
2. Гравець обирає роль.
3. Гравець додає до 5 супротивників.
4. Гравець обирає стадію матчу (early / mid / late).
5. Гравець натискає «Показати варіанти».

**Альтернативи:**
- Якщо поле обовʼязкове порожнє — показується помилка, запит не надсилається.
- Якщо герой не підтримується — показується попередження.
- Якщо патч не підтверджено — показується позначка «не перевірено».

**Постумови:** Параметри валідовані, запит надіслано до сервісу рекомендацій.

---

### UC-2: Отримати рекомендації

**Передумови:** UC-1 завершено успішно.

**Основний потік:**
1. Сервіс запитів перевіряє параметри.
2. Двигун рекомендацій шукає правила для поєднання героя/ролі/супротивників/стадії.
3. Генератор пояснень формує короткі причини для кожного варіанту.
4. Інтерфейс відображає картки рекомендацій із назвою, пріоритетом, причиною, версією даних.

**Альтернативи:**
- Якщо правил немає — показується повідомлення «Немає даних для обраного поєднання».
- Якщо дані застарілі — додається попередження.

**Постумови:** Гравець бачить список рекомендацій.

---

### UC-3: Переглянути пояснення

**Передумови:** UC-2 завершено, рекомендації відображені.

**Основний потік:**
1. Гравець клікає на картку рекомендації.
2. Розгортається детальне пояснення: правила, які спрацювали, джерело даних, приклад.

**Постумови:** Гравець розуміє, чому рекомендація була зроблена.

---

### UC-4: Оновити ігрові дані

**Передумови:** Вийшов новий патч Dota 2.

**Основний потік:**
1. Система оновлення даних завантажує нові дані героїв/предметів/здібностей.
2. Перевіряється сумісність правил рекомендацій.
3. Запускаються регресивні тести.
4. Версія даних оновлюється, CHANGELOG оновлюється.
5. Користувачам показується стан підтвердження.

**Постумови:** Система працює з актуальними даними.
