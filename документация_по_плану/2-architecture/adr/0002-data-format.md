# ADR-0002: Формат зберігання ігрових даних — JSON + версіонування

## Контекст

Ігрові дані (герої, предмети, здібності, правила) мають бути версіонованими, оновлюваними після патчів і легкими для тестування.

## Варіанти

| Варіант | Плюси | Мінуси |
|---|---|---|
| JSON файли в репозиторії | Простота, версійність через git, легко тестувати | Розмір репозиторію, не для великих даних |
| SQLite / БД | Запити, індекси, міграції | Складність версіонування схем, розгортання |
| Redis / Key-Value | Швидкість, TTL | Персистентність, версіонування |
| Зовнішній API (OpenDota, Stratz) | Актуальність, не потрібно підтримувати | Залежність від третіх сторін, rate limits, офлайн |

## Рішення

**Обрано: JSON файли в репозиторії (або окремому data-репозиторії) з версіонуванням.**

Структура:
```
/data
  /7.37d
    heroes.json
    items.json
    abilities.json
    rules.json
  manifest.json  # { current: "7.37d", updated: "2026-11-16", source: "..." }
```

## Наслідки

- Data Store завантажує JSON при старті, кешує в пам'яті.
- Оновлення: додати нову папку версії, оновити manifest.
- Регресивні тести запускаються на кожній версії даних.
- Розмір даних Dota 2 — приємний для JSON (місяць гігантів).
