# ADR-0001: Архітектурний стиль — Монолітний багатошаровий

## Контекст

Потрібно обрати архітектурний стиль для MVP ШІ-помічника Dota 2. Команда невелика (2-4 люди), терміни стислі, продукт — навчальний прототип.

## Варіанти

| Варіант | Плюси | Мінуси |
|---|---|---|
| Монолітний багатошаровий | Простота розгортання, тестування, розробки; одна кодова база | Обмежене масштабування, зв'язність модулів |
| Клієнт-серверний (API + UI) | Чітке розділення, можливість кількох клієнтів | Додаткова складність (мережа, версіонування API) |
| Мікросервіси | Незалежне розгортання, масштабування | Надлишкова складність для MVP, операційні витрати |

## Рішення

**Обрано: Монолітний багатошаровий** для MVP.

- UI, API, бізнес-логіка, доступ до даних — в одному застосунку.
- Чіткі межі модулів (шари) через інтерфейси.
- Можлива пізніша міграція до клієнт-серверного, якщо знадобиться overlay або мобільний клієнт.

## Наслідки

- Простіший CI/CD (один артефакт).
- Тестування: юніт-тести модулів + інтеграційні тести шарів.
- Розгортання: один контейнер / процес.
- Ризик: якщо UI і API будуть розділені пізніше — потрібно виділити контракт API заздалегідь (виконано в `api.md`).
